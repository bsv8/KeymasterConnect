# 安全模型

- 出所：情報は設定の正確 origin と現在 Session Window の両方に由来しなければなりません。
- ウォレット身份：ネットワークと公開鍵が共同確定します。main／test の同一公開鍵記録は隔離され、既定ネットワークに後退しません。
- 位置決めと認可：裸公開鍵は位置決め専用であり、実行は現在身份・実際出所・確認・署名を再核対します。旧実行ハンドルは同鍵再取込で回復しません。
- アプリ身份：Storage と MSFile は発行者署名 proof を要求します。回復時は既存 proof を再検証し、未署名引数の追加で身份を昇格できません。
- ユーザー確認：支払文案と認可方針は Keymaster が統制し、アプリは支払を通常操作に偽装できません。
- 秘密鍵：SDK が取得するのは公開身份・署名・暗号文・情報・結果のみであり、秘密鍵や再利用可能な共有秘密を永遠に取得しません。

外部証憑は検証者が身份・署名・範囲・証憑自身の有効期限で検証します。ローカル初期化やログアウトは発行済み材料を書換えず、旧ローカル設定も回復しません。
