# セッション

アプリは Keymaster origin に接続し、ユーザー認可後に現在ウォレット `{ bsvNetwork, publicKeyHex }` を取得します。アプリは秘密鍵やネットワークを選択しません。

| 階層 | ライフサイクル |
| --- | --- |
| ウォレット身份 | 公開鍵と初期化時ネットワークが確定。main／test の同一公開鍵は別身份 |
| ウォレット世代 | 初期化で変化。同一鍵の再取込は旧実行認可を継承しない |
| ローカル接続記録 | 現在 origin の claims と検証済みアプリ proof。譲渡可能トークンではない |
| 転送紐付け | 受信端が実際 origin・ウィンドウ・ウォレット・Worker 世代で発行。SDK が自動使用 |
| アンロック実行期 | ウォレット施錠や Worker 再起動後は受控操作能力を再取得する |

## ログインと再開

```ts
const session = await keymaster.login({ text: "ウォレットに接続" });
const resumed = await keymaster.resume();
// Storage / MSFile 利用時：
const appSession = await keymaster.resume({ appIdentity });
```

三種の確立経路 `login / resume / launch` はいずれも `networkIdentity` と claims 等の結果を返し、SDK は返却身份に紐付けます。
業務メソッドにウォレット位置決め引数はありません。`connect()` と ready は転送可用のみ示し、認可成功の意味ではありません。

再開は現在ウォレットと現在 origin のローカル記録を読取ります。キャッシュ空時は現在既定コンテキストのみ再構築し、削除済み claims・限度・実行ハンドルは回復しません。発行者 proof は再検証必須であり、未署名の追加引数でアプリ権限を取得できません。

## 身份変化

ウォレット初期化・再初期化・Worker 再起動後、旧紐付け・待機リクエスト・イベントを新身份に自動移行してはなりません。
同一秘密鍵の再取込でも旧実行認可は失効します。アプリは明示的に再接続し、新返却身份を読取って自判断・案内しなければなりません。

初期化は外部保有の署名済み材料を書換えません。検証者は公開鍵・ネットワーク・署名・範囲・証憑自身の有効期限で検証します。
接続結果と裸公開鍵は無確認支払証憑ではありません。

## ログアウトと終了

`logout()` は現在 origin のローカル接続と関連実行認可を取消します。ウォレット公開鍵引数は受付けません。
`close()` は転送終了と SDK ローカル紐付け掃除のみであり、ログアウトしません。再開後は `resume()` するか再ログインしてから業務リクエストを送信してください。
