# リリースノート

現在公開版本は `0.1.4`、源符号は `0.1.5` 選択加密保存候補、wire はいずれも v1 です。包版本と wire 版本は分別管理し、製品未上线、wire は 1 維持、削除欄互換分岐は維持しません。

## 0.1.5 候補（wire v1 不変）

- 支払は outputs 模型に変更：`payment.pay` は `{ clientRequestId, outputs: [{ amount, script }] }`、順序がチェーン上順序、お釣りはウォレット追加。`channelId/paymentType/businessKind/amountSatoshis/recipient/feeRate` 欄および `payment.channel.register`・`p2pkh.transfer` 公開入口とクライアント封裝を削除。
- 選択加密保存の追加：`storage.encrypted.put/get`（`client.storagePutEncrypted/storageGetEncrypted`）は通常 put／get と同一の平文引数を受理し、ウォレット Vault が暗号化して保存、復号して返却します。`0.1.4` 受信端は新メソッドを拒否します。発行前は隔離候補包でのみ検証します。
- 共用脚本解釈庫 `keymaster-connect/script`（`interpretLockingScript`）の追加：P2PKH／P2PK／標準マルチシグ／OP_RETURN／未知脚本の完全一致解釈であり、ウォレットと CLI Web の表示専用。支払可否を決定しません。

## 0.1.4 公開発行済（wire v1）

- AI 道具の追加：`client.registerTools([...])`、`[]` 提出は注銷。切断や紐付け変化後は再登録必須、旧呼出は再演しません。服務端は `KeymasterAiToolReceiver` を提供します。
- 接続模式の完成：アプリ主动接続は既定で完全ウォレットホーム頁 `/` を開き、専用プロトコル頁に入りません。SDK はウォレットウィンドウを終了せず、`close()`・錯誤・タイムアウトは転送終了と元申請の努力取消のみ行います。ready 待機はウォレット初期化とアンロックを包含し、既定二分です。
- 独立両端協約依託：Client・本番受信端・公開契約・引数検証を倉庫根 `src` に統一し、包は根入口・`/protocol`・`/server`・`/script` を提供。隣接ウォレット源符号に依存しません。

## 履歴

### 完全ウォレット接続（0.1.2 候補、0.1.4 に代替、プロトコル v1 維持）

- アプリ主动接続は既定で完全ウォレットホーム頁を開き、専用プロトコル頁に入りません。
- SDK はウォレットウィンドウを終了しません。close・錯誤・タイムアウトは転送終了のみ行い、元申請を努力取消します。
- 既定で各クライアントは自ウォレット文書を開き、跨アプリ命名ウィンドウ再利用による opener 誤継承を回避します。専用ポップアップ寸法設定を削除。
- ready 待機はウォレット初期化とアンロックを包含し、既定二分です。
- 受信端の実際業務認可は完全ウォレットが担当し、SDK は秘密鍵や内部承認能力を取得しません。
- 0.1.2 は候補であり、公開発行されず、0.1.4 に代替されました。候補包の検証は公開 npm 発行と等価ではありません。

## 独立両端協約依託と単ウォレット API（プロトコル v1 維持）

- Client・本番受信端・公開契約・引数検証を倉庫根 `src` に統一し、ウォレットは同一受信端を消費します。業務認可と署名は SDK に移りません。
- 包は根入口・`/protocol`・`/server`（`/script` は 0.1.5 で追加）を提供し、隣接ウォレット源符号に依存しません。文書生成も当倉源符号のみ読取ります。
- 当時の公開版本は 0.1.1 でした。包版本と wire 版本は分別管理し、製品未上线、wire は 1 維持。
- 初期化は信頼 Keymaster `targetOrigin` のみ指定し、`networkIdentity` 選択肢を削除。
- 初回ログイン・再開・appView 起動は公開鍵やネットワークの事前知識が不要であり、成功結果はいずれも `networkIdentity` で返却します。アプリが自判断・案内します。
- 重複する接続結果 `walletPublicKeyHex`・`ownerPublicKeyHex` を削除し、`result.networkIdentity.publicKeyHex` を使用します。
- すべての公開業務引数のウォレット位置決め欄を削除し、ネットワーク切替 `assetId` も削除。
- `resume(params?)` は必要なアプリ proof のみ保持し、公開鍵文字列を受付けません。`logout()` は公開鍵を受付けません。
- SDK は受信端の一時接続紐付けを自動使用し、情報出所・ウィンドウ・紐付け・身份を持続検証します。アプリは紐付けを保存・再演しません。
- 初期化・再初期化・Worker 再起動後、旧紐付けは失効します。同一公開鍵の再取込は旧実行認可を継承しません。
- `ready` は転送可用のみ示し、`close()` は注銷を代替しません。
- 旧 API／プロトコル互換層を提供しません。SDK と Keymaster は発行境界で配套検証しなければなりません。完全ウォレット頁経路と wire 版本は独立です。

移行（当時）：旧構造選択肢と業務公開鍵／ネットワーク引数を削除し、接続成功後に `networkIdentity` を読取る方式に変更。新規ウィンドウでは再開またはログインしてから業務を呼出してください。（支払通路模型は 0.1.5 で outputs に変更。上参照。）
